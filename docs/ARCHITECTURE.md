# Архитектура и путь внедрения

## Схема

```
CMS-ключ "kids_fun_layer" (JSON)          CDN: спрайты, Lottie, звуки
            │                                      │
            ▼                                      ▼
   ConfigLoader ── ConfigValidator ──► FunConfig   AssetStore (sha256, кэш)
            │            (ядро)                    │
            ▼                                      │
        EggEngine ◄── детекторы (ядро) ◄── датчики/касания платформы
   (экран, расписание, кулдаун,                    │
    веса, прогресс, подсказки)                     │
            │ PlayDecision                         │
            ▼                                      ▼
   EffectRuntime: ParticleField / GhostField / Lottie / Fog  ──► окно-оверлей
            │
            ▼
   Тост «1 из 5» ──► шторка: коллекция + загадка + «Похвастаться»
```

Слои:

| Слой | iOS (в репозитории) | Android (план) | Общее |
|------|---------------------|----------------|-------|
| Ядро | `FunLayerCore` (Swift, только Foundation) | `funlayer-core` (Kotlin, только stdlib + org.json) | алгоритмы, лимиты, тесты, JSON |
| Датчики | CoreMotion `deviceMotion` | `SensorManager` `TYPE_LINEAR_ACCELERATION`, `TYPE_GRAVITY` | без разрешений |
| Удержание аватарки | `UILongPressGestureRecognizer` на аватарке → `reportHold` | `Modifier.pointerInput { detectTapGestures(onPress = …) }` → `reportHold` | `HoldDetector` в ядре |
| Оверлей | отдельный `UIWindow` с пропуском касаний | `Box` поверх `NavHost` в корневом Compose | касания проходят насквозь |
| Частицы/призраки | SwiftUI `Canvas` + `TimelineView` | Compose `Canvas` + `withFrameNanos` | физика из ядра |
| Персонажи | Lottie (`LottieAnimationView`) | Lottie (`LottieAnimation`) | один `.json` |
| Звук/вибрация | `AVAudioPlayer` (.ambient), `UIFeedbackGenerator` | существующие в приложении | — |
| Хранилище | `UserDefaults` | `DataStore`/`SharedPreferences` | `KeyValueStore` |

## Интеграция в приложение

```swift
// 1. при старте, когда есть окно
FunLayer.shared.install(on: window)

// 2. при каждой смене экрана (из роутера/координатора)
FunLayer.shared.setScreen("main")      // "content", "profile", "transfer" …

// 3. из списков с pull-to-refresh (только «Контент»)
FunLayer.shared.reportPull(distance: overscroll)

// 4. из существующих обработчиков нажатий
FunLayer.shared.reportTap("settings.version")                     // нажатие на «Версия приложения»
FunLayer.shared.reportHold("profile.avatar", .began, at: point)   // long-press на аватарке: .began / .moved / .ended
```

Существующие экраны не меняются. Экранам нужно лишь сообщать свой идентификатор — обычно это одна строка в навигации.

## Решения и почему

**Отдельное окно-оверлей, а не модификация экранов.** Слой не знает о вёрстке приложения, а приложение — о слое. Окно возвращает `nil` из `hitTest` везде, кроме интерактивных элементов: кнопки и прокрутка под эффектом работают как обычно. Это и есть «слой поверх, а не ещё один экран».

**Физика в ядре, рендеринг на платформе.** Позиции частиц и призраков считаются аналитически от времени рождения — пропущенный на слабом телефоне кадр не ломает анимацию. Ядро покрыто тестами и одинаково на обеих платформах; платформенный код — только рисование.

**Персонажи — Lottie.** Lottie уже в стеке СберKids на обеих платформах. Дизайнер рисует в After Effects + Bodymovin, файл кладётся на CDN — новый персонаж без релиза. На iOS Lottie по умолчанию использует Core Animation: анимация считается системным рендер-сервером, CPU почти не тратится. Обезьяна в демо сгенерирована скриптом `tools/make_monkey_lottie.py` (скелет из 17 костей, запечённые позы) — доказательство, что формат покрывает «паркур + сальто + ловля».

**Детекторы жестов — конечные автоматы без системных API.** Тряска — N пиков линейного ускорения в окне с гистерезисом (ходьба ~0,45 g не срабатывает, тест). Ладонь — ≥ 3 касаний или одно пятно ≥ 30 pt, почти без движения, дольше 1,2 с; срабатывает на отпускании. Удержание ленты — порог перетяга + время. Все пороги — в конфиге.

**Почему призраки — удержание аватарки.** Перепробовали всё. Датчика освещённости в публичном API iOS нет, датчик приближения на iPhone гасит экран. Ладонь iOS и многие Android отбрасывают как крупное касание (palm rejection) — срабатывает через раз и задевает кнопки. «Экраном вниз» надёжно, но ребёнок сам не догадается. Круги и спираль пальцем мешают обычной прокрутке и путаются с ней. Удержание своей аватарки 5 секунд — обычный long-press на любом телефоне: случайно так никто не держит, а загадка «зажми свою аватарку и не отпускай» понятна ребёнку. Первую секунду ничего не видно (обычное нажатие никто не заметит), потом туман у пальца, глазки и «тук» каждую секунду — ребёнок понимает, что надо держать дальше. Через 0,25 с удержания прокрутка блокируется, палец может немного сдвинуться — отсчёт не сбрасывается.

**Персонажи Lottie — в UIKit-слое под SwiftUI-оверлеем.** Через `UIViewRepresentable` анимация вставлялась на 2–3,5 с позже, пока палец держал ленту, а страховочный таймер обрывал её на лету. Теперь `LottieAnimationView` создаётся и запускается в момент срабатывания, конец — по её собственному завершению. Проверено UI-тестом с настоящим жестом «потянуть и не отпускать».

**Атомарная смена конфига.** Новый конфиг включается, только если прошёл валидацию и скачались все его ресурсы (с проверкой sha256). Иначе работает прежний. Встроенный в сборку конфиг — последняя линия обороны.

## Что переиспользуется и что нужно построить

| Переиспользуется из приложения | Нужно построить |
|--------------------------------|-----------------|
| Lottie, звуки, вибрация | модуль `FunLayer` (~1,2 тыс. строк на платформу) |
| Механизм CMS-ключей (произвольный JSON) | ключ `kids_fun_layer` в CMS |
| CDN для статики | папка ресурсов эффектов |
| Навигация (идентификаторы экранов) | вызов `setScreen` из роутера |
| Pull-to-refresh в ленте контента | вызов `reportPull` |

Новые эндпоинты, контракты, разрешения, SDK — **не нужны**.

## Оценка объёма

| Работа | iOS | Android |
|--------|-----|---------|
| Ядро | готово (этот репозиторий) | перенос 1:1, 2–3 дня с тестами |
| Оверлей, рендер, датчики | готово (прототип), доводка 3–4 дня | 5–6 дней |
| Интеграция, QA, a11y | 2–3 дня | 2–3 дня |
| Контент (новые пасхалки) | без разработки: конфиг + ассеты | то же |
